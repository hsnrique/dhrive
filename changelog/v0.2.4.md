title: One task, split across your CLIs
---
### The maestro
- Write a task once in Terminals and a CLI and model of your choice splits it into subtasks. It only reads the project.
- Pick the CLI and model for each subtask, read and edit it at full size, and point the maestro at the skills, MCP servers and plugins that matter.
- Approve and run: each subtask opens as a pane already at work, in a git worktree on its own branch. The split stays until you clear it.

### Bring it together
- One click commits each pane's work and merges every branch onto one, without touching the branch you have checked out.
- A conflict is named with its files and opens in a pane to resolve. The result goes to a pull request in one more click.

### Terminals live in your projects
- Terminals sessions sit in each project next to its conversations, each marked as what it is, and are kept between launches.
- Sessions the CLIs ran for dhrive (the maestro's, the panes') no longer show up as conversations, and any CLI session can be taken off the list.
- A CLI that's signed out says so in one line, with the command to sign back in.
